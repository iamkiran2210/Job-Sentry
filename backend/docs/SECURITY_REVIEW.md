# Security review

Reviewed source: authentication, dependencies, API middleware, resume upload/storage, Celery configuration, candidate verification, and current tests. This is a code review record, not a third-party assessment.

| Area | Control found | Gap | Fix in this pass | Test |
|---|---|---|---|---|
| Authentication and token lifecycle | Password hashes use Argon2. Refresh tokens are stored hashed and rotated/revoked. JWT algorithm is pinned to configured `JWT_ALGORITHM`. | Login throttling and password-change revocation are not present; there is no password-change endpoint. | Cap access tokens at 15 minutes, refresh tokens at 7 days, validate `iat`/`iss`/`aud`, pad missing/provider account login with a dummy Argon2 verification, use generic auth failures, and require company-admin authorization for registration. Logout is authenticated and only revokes the caller's token. Google identity linking requires an authenticated account with the same verified email. | `tests/test_security_hardening.py::test_access_tokens_have_bounded_lifetime_and_validated_issuer_audience`; `tests/test_auth.py::test_login_failure_is_generic_for_unknown_and_provider_accounts`; `tests/test_auth.py::test_registration_requires_company_admin`; `tests/test_auth.py::test_logout_requires_authentication`; `tests/test_auth.py::test_google_link_cannot_issue_tokens_for_another_account` |
| Tenant isolation | Resource services generally scope by authenticated user's company; status and candidate-intelligence tests cover cross-company access. | No suite test enumerates every resource route and proves company isolation. | No comprehensive tenant-route test in this pass. | NOT VERIFIED: route-wide tenant enumeration test is still required. |
