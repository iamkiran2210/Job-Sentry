# Security review

Reviewed source: authentication, dependencies, API middleware, resume upload/storage, Celery configuration, candidate verification, and current tests. This is a code review record, not a third-party assessment.

| Area | Control found | Gap | Fix in this pass | Test |
|---|---|---|---|---|
| Authentication and token lifecycle | Password hashes use Argon2. Refresh tokens are stored hashed and rotated/revoked. JWT algorithm is pinned to configured `JWT_ALGORITHM`. | Access lifetime was configurable above 15 minutes; issuer, audience, and `iat` were not required. Login throttling and password-change revocation are not present. Provider-only login gives a different failure message. | Cap access tokens at 15 minutes, refresh tokens at 7 days, add issuer/audience and require `iat`, `iss`, `aud`; production settings reject placeholder/short secrets. | `tests/test_security_hardening.py::test_access_tokens_have_bounded_lifetime_and_validated_issuer_audience`; `tests/test_security_hardening.py::test_production_settings_reject_missing_short_or_placeholder_secret` |
| Tenant isolation | Resource services generally scope by authenticated user's company; status and candidate-intelligence tests cover cross-company access. | No suite test enumerates every resource route and proves tenant isolation. | No comprehensive change in this pass. | NOT VERIFIED: route-wide tenant enumeration test is still required. |
| Authorization | Resource APIs use authenticated-user and role dependencies in the reviewed modules. | Public registration, Google login/registration, and logout routes are not all represented by the security review's allowed public-route list; route-wide auth enumeration is absent. | No route-wide policy change in this pass. | NOT VERIFIED: OpenAPI route-auth enumeration and role matrix coverage are incomplete. |
| File access | Resume objects are stored via storage abstractions; upload routes require an authenticated user and job access. No public static resume mount was found. | Path traversal and symlink tests for every storage backend, and authorization tests for any future download path, are absent. | No storage changes in this pass. | NOT VERIFIED: traversal test matrix. |
| Upload validation | Resume ingestion checks size, extension, detected content, and reads in bounded chunks; rejected files are not passed to ingestion. | End-to-end proof of early `Content-Length` rejection, mid-stream abort cleanup, archive/page/decompression limits, and all corrupt-file cases is incomplete. | No upload changes in this pass. | NOT VERIFIED: upload security matrix. |
| Rate limiting | No Redis-backed request limiter was found. | Login, upload, rank, compare, and default limits are absent. | No limiter added in this pass. | NOT VERIFIED: all rate-limit tests. |
| CORS | Origins come from settings. | Local-origin regex broadened the configured list; methods and headers used wildcards while credentials were enabled. | Removed the regex and configured explicit methods and headers. | `tests/test_security_hardening.py::test_cors_rejects_origins_outside_the_configured_list` |
| Secrets and configuration | `.env` is not listed among tracked files in this checkout. Production startup now rejects short/known placeholder JWT secrets and forces debug and docs off. | Secret scanning tools and production startup integration tests are unavailable/not run. | Added production settings validation and conditional docs routes. | `tests/test_security_hardening.py::test_production_settings_reject_missing_short_or_placeholder_secret`; `tests/test_security_hardening.py::test_production_settings_force_debug_and_docs_off` |
| Headers and transport | API responses now receive `nosniff`, frame denial, referrer policy, and JSON `no-store`. | Trusted host/proxy configuration and a request-body limit are absent. | Added security-header middleware. | `tests/test_security_hardening.py::test_security_headers_are_added_to_json_responses` |
| Injection and serialization | Celery is configured for JSON serialization only. Candidate URL checks include SSRF validation. | A complete raw-SQL/dynamic-query audit and dependency audit have not been completed in this stage. | No broad query changes in this pass. | NOT VERIFIED: complete injection/dependency audit. |
| Logs and reporting | Request logs use route templates, request IDs, and recursive sensitive-key redaction. | Error reporter/Sentry integration, task ID/request ID propagation, and a failed-login password-capture test are missing. | No external reporting client was added. | NOT VERIFIED: reporter and task-log tests. |

The remaining gaps above are open work, not assurances that the listed controls are sufficient.
